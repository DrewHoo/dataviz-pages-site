# Build-time data fetching with scheduled refresh

Read this when the site's JSON content changes over time (prices, sports stats, scraped public data) and needs periodic refresh. The pattern is: **fetch + bake at build time** rather than fetch at runtime. Data ships as static JSON in the artifact; the workflow regenerates it on every deploy + every scheduled run.

## Script structure (`scripts/fetch-data.mjs`)

```js
// Fan out with bounded concurrency — avoids hammering source APIs.
const CONCURRENCY = 5
async function runWithConcurrency(items, limit, worker) {
  const results = new Array(items.length)
  let cursor = 0
  const pull = async () => {
    while (true) {
      const i = cursor++
      if (i >= items.length) return
      try { results[i] = { ok: true, value: await worker(items[i], i) } }
      catch (err) { results[i] = { ok: false, item: items[i], error: err.message } }
    }
  }
  await Promise.all(Array.from({ length: limit }, pull))
  return results
}

async function main() {

  const results = await runWithConcurrency(ITEMS, CONCURRENCY, processOne)

  const summaries = results.filter(r => r.ok).map(r => r.value)
  const failures  = results.filter(r => !r.ok)

  // Write an index.json with summaries for fast lazy-loading in the UI.
  await writeFile(resolve(OUT_DIR, 'index.json'), JSON.stringify({
    generatedAt: new Date().toISOString(),
    items: summaries,
  }, null, 2))

  if (failures.length) {
    console.log(`Skipped ${failures.length}:`)
    for (const f of failures) console.log(`  ${f.item.key.padEnd(10)} ${f.error}`)
    // Decide: continue or fail the build. For best-effort sites, don't fail.
  }
}

main().catch(err => { console.error(err); process.exit(1) })
```

## Wire it into the build

```json
"scripts": {
  "dev": "vite",
  "fetch": "node scripts/fetch-data.mjs",
  "build": "node scripts/fetch-data.mjs && vite build",
  "build:no-fetch": "vite build"
}
```

`npm run build` does both. `npm run build:no-fetch` is for tight iteration on UI when the cached data is fine. `npm run fetch` is what the user types when they want fresh local data.

## Gitignore the generated data

```gitignore
node_modules
dist
.vite
.DS_Store
*.log

# Generated by `npm run fetch` (or implicitly by `npm run build`).
# Kept out of git so the repo doesn't bloat as the universe grows;
# CI regenerates these on every deploy.
public/data/
```

Reason: a daily refresh of ~250 tickers × ~150KB each is ~37MB *added to git history per refresh*. Over a year that's ~13GB in `.git/objects`. Gitignoring keeps the repo slim — CI generates fresh artifacts each deploy.

## Schedule the refresh

`schedule: - cron: '30 22 * * 1-5'` in the deploy workflow runs weekday evenings after US close. Adjust for other domains (e.g., crypto: `0 */4 * * *` for every 4 hours; CFB stats: weekly).

## Local UI dev with stale data

Run `npm run fetch` once to populate `public/data/` locally, then `npm run dev`. Vite serves the public dir as-is.
